# W1 outdoor world index import and seam diagnostics

## Outcome

W1 now imports all four pinned Tiled `.world` files into
`dist/world-index.json` without changing runtime behavior. The artifact uses
the `pocket-tuxemon/outdoor-world-index/v1` contract, is included in
`pak.json`, and is covered by the production two-cook determinism check.

The importer treats `.world` coordinates as placement data but treats each TMX
root as authoritative for dimensions and `inside`. It emits:

- corrected outdoor map rectangles in tile coordinates;
- normalized source cardinal declarations and their resolved targets;
- symmetric adjacency and evidence-backed topology seams;
- every original TMX `transition_teleport` from an outdoor member;
- per-opening handoff compatibility, so a topology seam is not automatically
  interpreted as a safe coordinate-preserving crossing;
- rejected edge contacts, linked gaps, overlaps, dimension corrections, and
  ambiguous cardinal aliases, each with a concrete reason; and
- a canonical SHA-256 over the complete payload except the hash field itself.

The final artifact is 536,616 bytes. Its declared content hash is
`c681c230fe432bbbf8809fe11a5bbc42fc8eb4f62c2ec1a6be141fd0c35f2143`;
the serialized file SHA-256 is
`daba4583c444da9a8ef06ab14a8b3887abc351afb3fa10eb15f347baa40a2a25`.

## Diagnostic decisions

- A seam requires corrected rectangles to share exactly one edge with positive
  projected overlap, plus either an edge-aligned TMX teleport to the other map
  or a cardinal declaration resolved to that map. Same-name YAML overlays stay
  in the ordinary project import but cannot assert physical world topology.
- Normal Route 1 ↔ Taba Town is rejected as `portal-away-from-edge`; its door
  teleports remain ordinary portals.
- Spyder Candy Port ↔ Diamond Hill is rejected as
  `wrong-side-direction` because the declaration points to the opposite edge.
- Thirteen portal-linked nonadjacent pairs and the unique cardinal-linked
  Spyder Diamond Hill → Route C pair are recorded as gaps, never seams.
- Cardinal aliases resolve by exact map ID first, then a unique geometrically
  aligned slug, then a unique slug. This prevents Eclipse's repeated
  `lion_mountain`/`park` slugs from fanning out into false gaps. The sole
  unresolved declaration, Eclipse Obsidian Town `east=lion_mountain`, is an
  explicit ambiguity diagnostic listing its three candidates.
- Forty-nine `.world` dimensions are corrected from TMX: 46 zero-sized entries
  and three nonzero stale entries. Twenty corrections are outdoor. In
  particular, `spyder_routeb` changes from 256×640 source pixels to its actual
  20×40 tiles (320×640 pixels).

## Contract and validation

`importer/world-schema.ts` is the consumer contract for W2. Validation is both
structural and relational: it recomputes rectangle relations, local spans,
coordinate offsets, portal boundary contact, normalized cardinal resolution,
the complete evidence set, handoff compatibility, adjacency, ambiguity
diagnostics, linked-gap completeness, dimension corrections, and the canonical
content hash.

Mutation tests recompute the hash after corrupting semantic data. They prove
that an unrelated portal cannot authenticate a seam, fabricated cardinal
evidence is rejected, wrong geometry is rejected, and deleting a required
portal-linked gap is rejected. Synthetic geometry tests exercise exact-edge,
overlap, and gap branches even though the pinned corpus currently has no
overlap.

## Integration boundaries

World construction is isolated in `importer/world.ts`. `buildProject()` makes
one call and exposes the result beside the RPG Kit project; no world index is
inserted into the v1 project schema. `importer/index.ts` and `gen-assets.ts`
write the standalone artifact, while `tools/verify-g6-determinism.ts` includes
it in the two-cook snapshot. The existing `current_state` and `worldIdle`
implementation was not modified. Runtime halo loading and atomic handoff remain
W2+ work.
