## 2. Schema（`importer/time-weather.ts`）

按 S5 §5.2 的确定性状态模型定格式，运行时逻辑留给 D2：

```text
ClockState   = { mode: "game", refTick, epochDay, minuteOfDay(0..1439),
                 subMinuteTicks(0..ticksPerGameMinute-1), ticksPerGameMinute(>=1) }
WeatherState = { slug, enteredAtTick, nextTransitionTick(>=enteredAtTick), rngCursor(uint32) }
TimeWeatherState = { clock: ClockState, weather: WeatherState }
```

- 时钟是虚拟的：锚在 60 Hz 参考 tick 上（`refTick`/`subMinuteTicks`/`ticksPerGameMinute`），
  与 session hz 无关；默认 `ticksPerGameMinute=3600`（60 Hz 下 1 游戏分钟 = 1 真实分钟）。
  新档由 effect-shell 采一次墙钟写进这些字段，之后 reducer/render 绝不读墙钟。
- 天气用独立 PRNG cursor（`rngCursor`），与战斗 RNG 分开，战斗随机不会扰动天气序列。
- JSON codec 草案：`encodeTimeWeather`/`decodeTimeWeather`/`timeWeatherProblem`，
  支持 `{format, clock, weather}` 包装与裸 `{clock, weather}` 快照两种形态；
  校验逐字段报错（mode、minuteOfDay 范围、subMinuteTicks 范围、uint32 cursor、slug 在天气表内）。
  往返测试见 `tests/time-weather-schema.test.ts`。
- D2 把 `TimeWeatherState` 接进 `TuxemonExtensionState`（codec/migration），本任务不动现有 ext 状态。
