# K1 event-model extension report

## Result

The project format and pure reducer now support all six requested
RPG-Maker-style event capabilities without changing the
`rpgkit-project/v1` marker:

| Capability | Runtime semantics | Coverage |
| --- | --- | --- |
| Event areas | Optional `w`/`h` rectangles default to 1×1. Touch fires for each step into an area cell; action accepts the faced or occupied cell. | Unit tests cover multi-cell entry, latching, action, and a moving origin. The built fixture walks a two-hit strip. |
| Compound conditions | `condition.all` ANDs switch (including OFF), variable, self-switch, item, gold, and facing clauses with the existing flat page fields. | Unit and schema acceptance/rejection tests. |
| Facing conditions | Page selection and `if` use live facing. A facing-reading touch page re-evaluates on a turn in place; page sync, parallel cancellation, triggers, motion, and UI use the same facing. | Unit tests cover sideways crossing, in-place turning, action, branching, cancellation, and character page changes. |
| Per-visit locals | Switch and variable ids beginning `local.` are removed on initial entry and every transfer. | Unit and built-bundle transfer tests. |
| Event placement | `place` moves `"this"` or a named event, optionally changes facing, aborts a displaced forced-route waiter safely, and persists the override for the map visit. Page `dir` sets spawn/page-change facing. | Unit tests cover live, initially hidden, and page-facing cases; the built fixture checks the rendered NPC location before and after transfer. |
| Input lock | `lockInput` suppresses player movement and action starts across events; scripted touch, autorun, and parallel fibers continue. `unlockInput` restores control, and map entry clears the lock. | Unit and built-bundle tests verify frozen tile/pixel position, swallowed action, live parallel work, and release. |

The normative JSON schema, generated editor schema, public types,
top-level README, engine README, and format changelog describe the same
optional fields and three new commands (18 commands total). Existing v1
project documents remain valid.

## Save behavior

`inputLocked`, durable placements, and the transient placement queue are
part of interpreter state and deep validation. A held cross-event lock and
durable placements round-trip; a pending placement request is transient and
therefore not a safe save point.
Checksum-valid v1 saves written before these fields existed are hydrated
after checksum verification with only the missing safe defaults
(`false`, `{}`, `[]`). Explicitly malformed values still reach the
deep validator and are rejected.

## Deterministic built-bundle simulation

`tests/fixtures/event-model` is built through the normal PocketJS
pipeline. Its journey verifies all six capabilities against the real
bundle and includes:

- identical semantic milestones at 60/30/20/4 Hz;
- byte-identical framebuffer hashes across two clean boots;
- identical state and framebuffer hash sequences after restoring a
  mid-journey save;
- semantic pixel checks for player, placed NPC, ready status, and final
  status colors.

The final frame was also encoded as a task-local PNG artifact and inspected
visually. It shows the cyan player at (1,2), magenta NPC at (9,7), and

## QuickJS area-scan benchmark

The benchmark uses a release build of the real PocketJS desktop
`Runtime` and its QuickJS guest. It loads the built fixture at 480×272,
warms each case for 1,000 frames, and times `guest.frame(0)` for 10,000
frames. The map is 100×100 with 300 deterministic 3×2 touch areas; the
player rests inside `area-000`, so each measured area frame evaluates one
spatial candidate while the other 299 are rejected by the world-time cell
index. Autorun/parallel and actually displaced events remain dynamic
candidates, preserving behavior for moving content.

Command:

```sh
BENCH_FRAMES=10000 BENCH_WARMUP=1000 POCKETJS_DIST=dist \
  cargo test --release event_model_bench::area_scan -- \
  --ignored --exact --nocapture
```

Results:

| Case | n | mean | p50 | p95 | p99 | max |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Empty map (0 events) | 10,000 | 0.0250 ms | 0.0233 ms | 0.0272 ms | 0.0436 ms | 1.3830 ms |
| 300 area events | 10,000 | 0.0296 ms | 0.0288 ms | 0.0310 ms | 0.0386 ms | 1.2215 ms |
| Area minus empty | 10,000 | 0.0046 ms | — | 0.0037 ms | — | independent max outliers are not subtractable |

The total 300-event frame p95 is 0.0310 ms and the isolated p95 delta is
0.0037 ms, both below the 1 ms target. The reported maximum is the total
area-frame maximum, 1.2215 ms. Before indexing, the same harness measured a 2.3665 ms total p95
(2.3429 ms over baseline), which is why the world now compiles authored
areas into a per-cell trigger index instead of copying, sorting, and
scanning all events every frame.
