## Delivered behavior

- `Sheet.dirEdges` adds independent `enter` and `exit` edge masks while
  preserving the old, symmetric `dirBlock` contract. Passage cooking resolves
  terrain, overrides, and both directional masks into flat typed arrays once;
  manual movement, forced routes, and pathfinding all use the same crossing
  decision.
- `moveRoute` now targets `"this"`, `"player"`, or `{event: id}`. A waited
  cross-event route parks and resumes the publishing fiber; a fire-and-forget
  route returns immediately.
- Route steps now include `turnTowardPlayer`, `{turnToward}`, `{pathTo}`, and
  `{approach}`. Pathfinding is a deterministic four-neighbour BFS with a fixed
  down/left/up/right tie order, live body avoidance, bounded blocked-route
  retries/replanning, and approach-side/final-facing behavior.
- The 100x100 worst case is incremental: each active path search dequeues at
  most 250 cells per 60 Hz reference tick. The search state is plain cloneable
  data, and finishing it produces the same directions as synchronous BFS.
- The normative schema, editor copy, deep save validator, engine README, pure
  tests, built-bundle sim fixture, and benchmark fixture were updated together.
  Deep validation now accepts legal `{event: id}` route targets and rejects an
  empty event id or a non-positive approach distance.
- The earlier event-model review cases are covered end-to-end: a facing-gated
  mat stays inactive when crossed sideways and fires on an in-place turn; an
  `all` page remains inactive until every clause holds.

## Determinism and checkpoint evidence

The pure reducer and built bundle both run the K2 path/approach journey at
60/30/20 Hz. They assert the same final NPC cell and facing, and compare
completion time after converting host frames back to 60 Hz reference ticks;
the only permitted difference is the final partial host batch (at most two
ticks). The tests also cover one-sided BFS edges, synchronous/incremental path
identity, a player-owned `pathTo`, and replanning after a dynamic blocker moves.

Mid-route continuity is checked at two levels:

1. A pure `SessionState` is JSON-round-tripped while an NPC has a live route
   plan, then both the uninterrupted and restored states are folded for 200
   identical frames and compared structurally.
2. The built fixture snapshots the complete live session while the NPC is
   moving with an active plan, boots a fresh world, restores the checkpoint,
   and requires the same final state and the same 63 remaining host frames.

This is deliberately a **full runtime checkpoint test**, not a claim that the
public slot-save envelope supports arbitrary mid-route saves. Slot saves remain
safe-point-only; `snapshotFull`/`restoreFull` exist only in the test fixture to
prove that the live reducer state has deterministic serialization continuity.

The checks were mutation-tested and restored before the final gates:

- Replacing `sess.ticksPerFrame` with `1` made the pure multi-Hz test fail with
  a 194-reference-tick spread (`expected <= 2`) and, after rebuilding the real
  bundle, made its equivalent fail with a 132-tick spread.
- Dropping `chars` during full-state restore changed the resumed result from
  `done: true, frames: 63, npc: (2,6)` to
  `done: false, frames: 600, npc: (10,6)`.
- Forcing facing conditions true transferred the sideways-crossing player to
  `matreturn` instead of leaving it in `lab`; bypassing `condition.all` made
  `all-fired` true while `all-ready` was still false. Both sim cases failed.

## QuickJS performance

Measured in the release desktop host with the built `event-model` bundle, so
the guest code runs in QuickJS. Each case used 200 warm-up frames followed by
1,000 measured frames:

```sh
POCKETJS_DIST=/home/tangollvm/.fleet/worktrees/task-1824/dist \
BENCH_FRAMES=1000 BENCH_WARMUP=200 \
CARGO_TARGET_DIR=/var/tmp/fleet/1824/target \
cargo test --release k2_pathfind -- --ignored --nocapture
```

| QuickJS case | mean ms | p50 ms | p95 ms | p99 ms | max ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| One synchronous corner-to-corner BFS (10,000 cells) | 2.8865 | 2.8205 | 3.1223 | 3.1837 | **4.0545** |
| Ten synchronous BFS searches/frame (upper bound) | 22.3395 | 22.4963 | **23.7575** | 24.0895 | **24.6365** |
| Ten incremental BFS slices/frame (search kernel) | 0.7778 | 0.7724 | **0.8622** | 0.8862 | **0.9095** |
| Ten real event routes/frame (full session reducer) | 1.2917 | 1.4183 | **1.7118** | 1.7964 | **2.6015** |

The synchronous ten-search workload is far outside the 2 ms frame target,
which is why shipping routes use incremental BFS. The split search kernel is
below 1 ms even at its observed maximum. The realistic full-reducer workload
keeps p95 and p99 below 2 ms; one of 1,000 measured frames was a 2.6015 ms
outlier, so this report does not claim a strict all-frames maximum below 2 ms.

Harness: `/var/tmp/fleet/1824/quickjs-host/src/k2_path_bench.rs`.
