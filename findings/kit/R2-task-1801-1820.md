# R2：动画瓦片、16×32 行走角色与玩家名占位

## 结论

R2 已作为 Pocket RPG Kit 的通用能力完成。`GameView` 可从
`GameAssets.animated` 渲染按地图列出的动画格，原生 sprite atlas 负责
换帧，JS 仅在视口窗口变化时挂载、解绑和复用节点；动画不进入 reducer
或存档。玩家与 NPC 同时支持 16×16 和 16×32 的四朝向、三步态静态帧，
帧选择来自 reducer 保存的 facing/phase，脚底锚在占用格底边，upper 层与
`above: true` 动画仍能遮住伸入上一格的角色头部。

项目可配置 `playerName`。新游戏把它种入 switch bank，文本、选择提示和
选项中的每个 `{name}` 都会替换；没有配置时使用内置默认名，存档恢复时
保留存档里的名字并做 1–24 字符结构校验。

## 动画瓦片构建期

`tools/lib/animated.ts` 提供两部分：

- `cookAnimationAtlases` 接收 16×16 RGBA 帧序列，按像素、帧数与时序签名
  全局去重；帧横排并把列数补到 2 的幂，输出 PNG、稳定图集名以及
  `sprites.json` 的 `{ cols, rows: 1, frames, step, psm: 3 }`。
- `animatedManifestSource` 把每图 `{ x, y, above, sprite }` placement 稳定
  序列化为 `GameAssets.animated`；空图省略，也安全处理 `__proto__` 图 id。

`durationMs` 按固定 60 Hz 参考换成 `step = round(ms / 1000 * 60)`，至少
为 1。PocketJS 的一个原生 atlas 只能有一个 step，因此不等时长序列明确
降级为第一帧的时长。图集固定 PSM_8888；没有把动画帧压成 4444。

G5 的实际 `/home/tangollvm/.fleet/worktrees/task-1806/data/terrain-animations.json`
含 5,785 个 placement，每项已经提供 `x`、`y`、`above` 与
`frames[{tile,durationMs}]`。导入器只需把每个 tile id 解成 RGBA 后交给
cooker，再用返回的 `atlasFor` 填 sprite，形状无需再改运行时。

## 动画瓦片运行时

`AnimatedTiles` 为 below / above 各挂一层。每层在换图时只索引当前地图，
以共享的 `chunkWindow` 计算视口加一格 ring 的半开边界；窗口未变化时立即
返回。离开 ring 的节点先解绑进池，再供同一帧进入 ring 的格复用。atlas
名称绑定到原生 image 节点，帧推进不产生逐格 JS 更新。

`GameView` 的绘制顺序为：ground → below 动画 → NPC/玩家 → upper →
above 动画。诊断回调按层报告 map、mounted、created 和 pooled，供 sim 与
大地图集成测试断言。

## 16×32 角色

`loadWalkerSheet` / `sliceWalkerSheet` 默认读取 Tuxemon 的 48×128 sheet：

- 源行 down / left / right / up 转为引擎 down / left / up / right，映射
  为 `[0, 1, 3, 2]`；
- 源列 walk-left / idle / walk-right 转为三组、每组四朝向的 12 张 PNG；
- 输入尺寸、网格和自定义 layout 坐标均在构建期校验，同一输入产出字节
  稳定且不修改解码后的源像素。

schema 同时保留旧的 atlas walker 形态，并接受 build-time sheet walker
的 `sheet` id/path、`h`、`cols`、`rows`。运行时使用 `GameAssets.player`、
`playerHeight` 和 `npcSrc` 中已经切好的帧，不加载源 sheet。`PlayerSprite`
与 NPC image 都以 `insetT = 16 - height` 底部锚定；NPC 的当前页变化仍可
在静态图与 walker 间切换。

## QuickJS 基准

### 方法

基准使用钉住的 PocketJS `76ae741fb8fc` 桌面宿主真实 `Runtime`，包括
QuickJS `Guest`、`UiSurface` 与 offload。宿主源码只复制到
`/var/tmp/fleet/1820/host-bench` 并 include 本地测试 harness，没有修改
子模块。逻辑视口 960×544、density 2；64×40 地图的每个 below 格都为
动画，首帧断言视口 + 一格 ring 实际挂 2,135 个 below 节点和 1 个 above
节点。预热 60 帧，再测 600 帧；`guest.frame(0)` 为 JS 时间，
`surface.tick()` 单列 core 时间。

机器：Linux x86_64，Intel Xeon w5-3435X（32 逻辑 CPU），Bun 1.3.14，
Rust 1.98.1。复现命令：

```sh
bun tools/build-example.ts r2-ui
CARGO_TARGET_DIR=/var/tmp/fleet/1820/target \
POCKETJS_DIST="$PWD/dist" BENCH_FRAMES=600 \
cargo test --release --manifest-path /var/tmp/fleet/1820/host-bench/Cargo.toml \
  r2_ui_bench::full_screen_animation -- --ignored --exact --nocapture
```

### 结果

| 指标 | 960×544、满屏动画格 |
| --- | ---: |
| boot eval | 39.526 ms |
| 第一帧 JS / core（创建并绑定 2,136 节点） | 69.253 / 1.521 ms |
| 稳态 JS mean / p50 / p95 / p99 / max（600 帧） | 0.142 / 0.138 / 0.164 / 0.200 / 1.000 ms |
| 稳态 JS 超过 16.667 ms | 0 / 600 |
| 稳态 core mean / p95 / max | 0.000 / 0.000 / 0.001 ms |

结论是稳态动画成本不随帧数触发逐格 JS 更新；一次性全屏首次挂载有
69.253 ms 冷启动尖峰。正常地图切入仍应把它视为可见的单帧成本，后续若
真实 Tuxemon 地图在 PSP 上需要更平滑的首次出现，可在消费者侧用分帧
mount budget；本 R2 接口没有堵死该扩展。
