# R1：流式瓦片块（构建期编码 + 运行时按视口加载）

## 结论

R1 已实现为 Pocket RPG Kit 的可选通用渲染路径。生成器把地图的
ground / upper RGBA 块编码为 CLUT8 + PackBits RLE `TILESET` 条目，
`GameView` 在 `GameAssets.stream` 存在时才按相机窗口加载这些条目；
没有 `stream` 的现有游戏仍走原 `ChunkLayer`，数据格式和 reducer 均未改。

测试夹具包含 1024×640 的 `wide-field` 与 640×576 的
`violet-harbor`，可连续滚动并双向切图。其 3 个原始 TILESET 条目共
18,820 B，构建后的完整 pak 为 148,528 B。

## 构建期

`tools/lib/stream.ts` 提供：

- `encodeStreamedLayer`：接收固定边长、row-major 的 RGBA 块，默认
  256×256；透明像素规范化到索引 0，输出可直接放进 pak 的完整
  `TILESET` 条目以及运行时 refs。
- 一层不超过 256 色时共享一份调色板；超过后按非空块拆条目。同层
  完全相同的拆分块复用同一个条目/ref。若单块本身仍超过 256 色，
  频次优先、ABGR 次序打破平局，并用 RGBA 最近色作确定性量化，报告
  `quantized` 计数。
- 全透明块是 `null` ref；整层透明时不写条目。底层
  `encodeTilesetEntry` 负责 PackBits RLE 和相同索引流共享。
- `pakManifest`、`streamEntryFile` 与 `streamManifestSource` 分别生成
  稳定排序的 pak 行、稳定文件名和 `GameAssets.stream` 对象字面量。

`tests/stream.test.ts` 覆盖 RGBA 解码回环、透明/absent、两次编码字节
完全一致、跨 256 色拆分、相同块复用和全透明层。

## 运行时

`src/engine/chunk-window.ts` 把半开相机矩形、视口、像素边距映射为
clamp 后的 inclusive 块窗口，并提供窗口包含与整块扩张函数；没有
UI 或宿主依赖。

`StreamedChunkLayer` 的每层生命周期如下：

1. 请求窗口 = 视口 + 像素预取边距（默认 16px）。
2. 缺块按离视口中心的距离排序，再按可配置的每层/每帧上传预算调用
   `loadTileTexture`；未配置预算时不限。
3. 已加载块在请求窗口外再保留一整块作为滞回，离开保留窗口才调用
   `freeTileTexture`。
4. image 节点进入池中，滚动和切图时复用；ground 容器在角色下，
   upper 容器在角色上。

诊断回调报告 resident、textures、textureBytes、pool、created、uploads、
frees 与 pending。T8 纹理估算严格按每块 1,024 B 调色板 +
`chunkPx²` B 索引计算，因此 256px 块为 66,560 B。

`GameView` 仅在 `assets.stream` 存在时挂两层 `StreamedChunkLayer`；旧的
ground / upper `ChunkLayer` JSX 分支保持不变。新 API 从 `src/ui/index.ts`
导出，纯窗口函数从 `src/engine/index.ts` 导出。未修改
`vendor/pocketjs`。

## 集成夹具与画面

`tests/streamed-game-sim.test.ts` 在 wasm sim 中验证：

- 1024px 宽地图从 0 滚到 camera x=216、再到 x=536；边缘块颜色按
  预期进入画面。
- magenta upper 屋顶在滚动后仍遮住玩家，证明 z 序正确。
- ground 的滞回峰值创建 8 个节点，旧列释放后 resident 为 6，切图后
  节点总创建数仍为 8，证明池被复用。
- 切到第二张地图后 ground ref 与画面同时换成 harbor 色，upper 被
  释放；返回传送门供 QuickJS 反复切图。
- `loadBudget: 1` 时 ground 和 upper 各自每帧最多上传一块，pending
  随帧归零。

两张 480×272 golden 已逐张打开肉眼检查：`streamed.scroll.png` 是深绿、
绿、蓝的滚动块带且中心玩家被 magenta 屋顶遮挡；
`streamed.switch.png` 是紫/青 harbor 块且白色玩家可见。测试同时对这些
语义位置作 RGBA 断言，而不只比较哈希；整帧 FNV 分别为 `993600c5`
与 `e6c27225`。

## QuickJS 基准

### 方法

基准使用钉住的 PocketJS `76ae741f` 桌面宿主真实 `Runtime` / QuickJS。
只在 `/var/tmp/fleet/task-1793/host-bench` 复制宿主并 include 一个测试
harness，没有改子模块。密度为 1；每档先启动和预热 8 帧，再测空闲
240 帧、持续向右行走 360 帧以及 30 次双向地图切换。`guest.frame`
单独计为 JS 时间，`surface.tick` 单独计 core 时间；纹理峰值来自两层
实时诊断，QuickJS 堆由 `JS_ComputeMemoryUsage` 读取。

机器：Linux x86_64，Intel Xeon w5-3435X（32 逻辑 CPU），Bun 1.3.14，
Rust 1.98.1。复现命令（先生成并构建 fixture）：

```sh
bun tests/fixtures/streamed/gen-assets.ts
bun tools/build-example.ts streamed
POCKETJS_DIST="$PWD/dist" BENCH_W=480 BENCH_H=272 BENCH_SWITCHES=30 \
  cargo test --manifest-path /var/tmp/fleet/task-1793/host-bench/Cargo.toml \
  streamed_gameview_bench --release -- --ignored --nocapture
POCKETJS_DIST="$PWD/dist" BENCH_W=960 BENCH_H=544 BENCH_SWITCHES=30 \
  cargo test --manifest-path /var/tmp/fleet/task-1793/host-bench/Cargo.toml \
  streamed_gameview_bench --release -- --ignored --nocapture
```

### 与 S2 原型对照

S2 §2.3 的 chunk-only 原型 idle 为 0.016–0.020 ms，walking mean 为
0.017–0.040 ms。本夹具测量整个 `GameView` 帧（reducer、相机、角色与
UI 一起执行），所以稳定帧约 0.08–0.10 ms，不是仅流式窗口的微基准。

S2 的切图为 480 下 0.23–0.47 ms mean、最大 1.00 ms，960 下
0.42–1.28 ms mean、最坏 3.44 ms；本实现夹具最大 0.242 / 0.366 ms。
这不代表真实 Tuxemon 地图一定更快：当前夹具每次加载的是 4 块或
9–13 个简单块，而 S2 的最大用例一次上传 23 块。常驻峰值
0.60 / 0.87 MB 低于 S2 的 32 块、2.13 MB 上界；结束 QuickJS 堆也在
S2 的 0.90–1.76 MiB 范围内。
