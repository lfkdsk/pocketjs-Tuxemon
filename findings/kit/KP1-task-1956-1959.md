# KP1 — GameView first-mount QuickJS profile and startup optimization

## Result

PASS.

The startup bottleneck was not an unmounted battle/menu subtree or first-map
compilation. `createSession` synchronously recomputed SHA-256 over the
splitter-emitted 81,950-byte project shell even though the package already
contained its build-time manifest identity. On QuickJS, canonical JSON took
about 2.9 ms, while the pure-JavaScript SHA-256 took 85–87 ms.

Packaged shells now use their declared `mapManifestHash` as their content/save
identity. Missing declarations still take the computed fallback, and callers
accepting mutable or untrusted declarations can pass
`verifyMapManifest: true` to recompute and compare. Map-index validation is
always performed. The fallback SHA-256 implementation was also streamlined
for QuickJS.

On the current full Pocket Tuxemon bundle, median GameView mount fell from
103.844 to 21.517 ms at 480x272 and from 118.870 to 26.998 ms at 960x544.
That is a 79.3% / 77.3% reduction, with the node tree unchanged. Ten-run
startup-to-first-frame medians are 185.930 / 202.425 ms, below the 225 ms
target. On the GP1 fully sharded 992,015-byte JS bundle, the corresponding
medians are 124.042 / 135.899 ms and mount medians are 20.345 / 26.259 ms.

`tools/kp1-quickjs-bench.sh` copies the shipping desktop host into an isolated
scratch directory and includes `tools/kp1-quickjs-bench.rs`. Every sample
creates a fresh rquickjs `Guest`, feeds the real PAK, mounts the real host
services, evaluates the shipping bundle, and submits its first frame. Native
`Instant` is exposed only through the benchmark's optional hook, so the
measurements do not add a wall clock to reducer state. The hook also wraps the
native UI operations to count nodes and mutations. Normal applications do not
install the hook; a mark is only one optional global call and records no state.

`startup-to-first` includes bundle/PAK reads, surface/PAK setup, Guest and host
mounts, bundle evaluation (which synchronously mounts GameView), first QuickJS
frame, core tick, and first supervisor commit/hash. Percentiles use nearest
rank with the upper observation. All times below are milliseconds from
QuickJS, not Bun/JSC.

## Implementation

1. `resolveMapManifestHash(shell, verify)` validates a declaration's lowercase
   SHA-256 shape, directly returns a trusted package declaration by default,
   hashes shells that omit it, and recomputes/rejects stale declarations in
   strict mode.
2. `createSession` still validates every map-index row, duplicate id/entry,
   schema identity, start-map reference, initial map payload, registered
   extension/battle calls, world compilation, and passage table. Only the
   redundant digest was skipped.
3. `SessionOptions.verifyMapManifest` exposes strict mode without changing the
   old bare-repository overload. Tests cover trusted, strict mismatch,
   undeclared fallback, malformed hashes, and duplicate map ids.
4. SHA-256's compression loop now keeps the eight state words in local numbers
   and inlines rotates, avoiding helper calls and per-block destructuring in
   no-JIT QuickJS.
5. Optional phase marks cover session registration/index/manifest, map
   read/decode/validation/world/passage, startSession, view-model creation,
   actor and upper pools, animated and fixed-chunk ground layers, the
   persistent three-box dialog, complete tree construction, mount effects,
   and first commit. The streamed ground path is accounted by complete-tree
   construction plus the separately timed first QuickJS frame.

No UI subtree was newly deferred. The measured UI tree was only 18.3–23.6 ms
after the fix, while the 61-node dialog/choices/shop tree was 2.3–2.5 ms.
Keeping those nodes resident preserves PR #1's no-structural-op hot path and
avoids moving cost onto the first dialog/shop frame. The battle scene retains
its existing scene-gated mount; its entry/exit costs are reported below.
