# KR2：长 tape 倒带关键帧

## 结论

`AttractController` 现在按源 reducer 帧建立有界、运行时专用的完整关键帧。
默认每 3,600 源帧保存一次，并在地图切换及战斗进入/退出后立即保存。倒带从
目标之前最近的保留关键帧恢复 `SessionState`、held mask、tape/divergence 游标及
显示阶段/计时，再只通过原 reducer 折叠后缀。关键帧不进入存档格式。

默认关键帧预算为 8 MiB（确定性的 JSON payload 字节估算）；超限时按最旧优先
淘汰。目标早于最旧保留关键帧、单个关键帧大于预算或预算设为 0 时，明确回退到
从第 0 帧重折叠。`keyframeStats()`、`keyframeEstimatedBytes` 与
`rewindHistoryEstimatedBytes` 暴露预算、条目、淘汰数和最近一次后缀长度。

## 正确性

`tests/attract-keyframe.test.ts` 把 `keyframeMaxBytes: 0` 的旧式从零重折叠作为
oracle，对有关键帧路径逐字节比较 canonical 状态及所有控制器可观察量：phase、
demo/display/read/end 状态、held mask、`rewindNotice`、`controlNotice`、idle、
rewound 标志和输入前缀。覆盖：

- 固定种子的随机 6,000-frame tape，8 个倒带目标，60/30/20/4 Hz；
- 真实 Sunstone paced tape，5 个目标，60/30/20/4 Hz；
- takeover 后继续游玩、连续两次倒带及 SELECT 恢复；
- 地图切换、战斗进入、战斗退出边界，且四种 hz 的关键帧源帧一致；
- 小预算 FIFO 淘汰及目标早于保留窗口时的 frame-0 回退。

聚焦测试结果：`32 pass, 0 fail, 5310 expect() calls`。构建 Wasm 后的全量结果：
`922 pass, 0 fail, 467865 expect() calls`，没有 skip。现有 framebuffer golden
文件无改动；真实 Wasm sim/golden 用例均通过。

## 修复 1：补「倒带目标正好落在关键帧上」的边界测试

跨团队审查（`findings/review-task-1966.md`）判 FAIL：等价测试从未采样倒带目标恰好等于某个保留关键帧 `timelineFrame` 的情形（`lastRefoldFrames === 0` 的空后缀倒带）。`restoreTimeline()` 的后缀循环在空后缀时一次都不执行，此时 held mask（`lastFolded`）、display 游标（`displayTicks`/`stage`/`readHold`）、tape 游标（`demoFrame`）的恢复全靠关键帧 payload 里保存的显式值；删掉其中任何一行，`tsc` 仍 0 错误、原 7 个用例仍全绿。实现本身没有 bug，本次只补测试，不改实现。

新增 3 个用例（`tests/attract-keyframe.test.ts`，7 → 10 个）：

- **空后缀 held mask**：审查复现脚本的正式化。tape 前 10 帧按住 UP、其后 DOWN，关键帧间隔 10 源帧，倒带距离让目标正好落在 `timelineFrame=10` 的关键帧上（60/30/20/4 Hz）。断言 `lastRefoldFrames===0`、`lastRefoldStart===10`、`foldedMask()===BTN_UP`（关键帧保存的值，而非触发点残留的 DOWN）、`status().demoFrame===10`，并与 oracle 全量等价。
- **周期关键帧 δ=−1/0/+1**：autorun 长对话（120 字、`cps:15` 与 attract overlay 同速，源帧与时间线 1:1）让关键帧捕获时正处于打字阶段（stage 1、`displayTicks>0`）；tape 先按住 UP 再切 DOWN，使触发点的 held mask 与关键帧保存的不同。对 `sourceFrame=120/240` 两个抽样关键帧，倒带目标取 `timelineFrame−1/0/+1`，60/30/20/4 Hz，比较完整 canonical 状态 + 全部控制器可观察量（`foldedMask()`、`presentedModal()`、`status()` 含 `rewindNotice`/`demoFrame`/`readHold`、`inputLog`）。δ=0 断言空后缀且 `revealed` 落在打字中途；δ=−1 断言该关键帧被截断、从上一个关键帧（或 frame 0）重折叠；δ=+1 断言后缀恰从该关键帧开始。四种 hz 的关键帧 `sourceFrame`/`timelineFrame` 序列一致。
- **地图/战斗边界关键帧 δ=−1/0/+1**：地图切换、战斗进入、战斗退出三个边界关键帧，同样三档目标、四种 hz、全量等价；δ=0 断言空后缀。

触发点选择：低 hz 主机每步折叠多个源帧，目标长度未必可达，因此先用探针跑一遍记录每种 hz 实际到达的时间线长度，再取「≥ 下界且 `< tape.length`」的最早可达长度作为触发点——既保证触发点的 held mask/display 游标已偏离关键帧保存值，又保证 `demoFrame` 未到 tape 末尾（否则 `restoreTimeline` 结尾的 `Math.min(demoFrame, tape.length)` 钳制会掩盖错误的 tape 游标，这是本修复自查中发现并修掉的一个测试设计缺陷）。
