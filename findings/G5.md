# G5 terrain import: 263 TMX maps to streamed chunks and passage

## Result

G5 now imports the complete pinned Tuxemon terrain corpus without per-map edits. `bun run gen-assets` reads commit `9e6258ff726b786040a267e8bdbbf037b560285e`, writes 256 px streamed TILESET entries plus a `StreamedGameAssets` literal, and writes a terrain fragment that can replace placeholder terrain while preserving a G1 project's names and events.

G1 is not present on this branch. Therefore this delivery exposes and tests `applyTerrain(project, fragment)` instead of claiming that the final G1 document has already been wired. `data/terrain.json` is the handoff fragment; `ui/terrain-assets.ts` is the render-side handoff.

## Import rules

- Tile layers are composited in TMX document order. The index counts tile, object, image, and group layers exactly as pytmx does; visible tile layers with index `0..2` go below actors and indices `>2` go above them.
- Source alpha and layer opacity are retained through straight-alpha composition. Horizontal, vertical, and diagonal Tiled flip bits are applied before compositing.
- R2 animated-tile rendering is absent from the current Kit revision, so every animated reference is baked at its first declared frame. The full frame schedules are preserved separately in `data/terrain-animations.json` for R2.
- Each composed layer is cut into 256×256 RGBA chunks and passed to the Kit R1 `encodeStreamedLayer` implementation. Empty upper chunks remain `null`; all pak references are emitted by the Kit manifest helper.
- `applyTerrain` changes only the terrain-bearing fields (`ground`, `passage`, and the terrain sheet) and retains imported map names, events, and other project data.

The importer is dependency-free at generation time: `importer/xml.ts` parses the pinned TMX/TSX subset and `importer/png.ts` expands indexed 1/2/4/8-bit, grayscale, RGB, gray-alpha, and RGBA PNGs to straight RGBA.

## Collision conversion

The importer mirrors Tuxemon's load and movement order:

1. visible tile surface properties (`surfable`, `walkable`, `climbable`);
2. tile region properties (`enter_from`, `exit_from`, `endure`, slide and related region keys);
3. closed collision rectangles and polygon bounding rectangles, snapped with Python's ties-to-even rounding;
4. open collision polylines converted into blocked cell edges;
5. same-name YAML collision rectangles overlaid last, as Tuxemon's loader does.

An independent Python oracle parses raw TMX/TSX/YAML and reimplements Tuxemon `loader.py` plus `movement.py`. Across 11 deliberately varied maps it compared 56,176 directed moves with 0 mismatches, including polygon collisions (`gaming_hall`), 384 collision-line edges (`buddha_mountain`), labelled dynamic regions, directional regions, and the 21 YAML-only cells in `spyder_paper_manor`.

Four maps contain 14 labelled cells (`screen` or `volcoli`). These are intentionally omitted from immutable `map.passage`: G1 must materialise `collisionLabels` as removable blocking events so Tuxemon's `remove_collision` can open them.

There is one component-level limitation. Tuxemon permits asymmetric edges, while the current Kit `dirBlock` contract blocks both sides of a physical edge. The importer preserves every genuinely allowed direction and therefore leaves 1,161 reverse directions over-permissive across 25 maps, reporting each mismatch instead of silently closing legal paths. Follow-up proposal 1643 requests asymmetric directional passage support; it was recorded but was not enqueued during G5.

## Determinism and QuickJS performance

`tools/verify-terrain-determinism.ts` generated all outputs twice in isolated directories. Each run produced 435 files and 32,796,511 bytes; both trees had aggregate SHA-256 `121cb983ed8411b48bb53fb8b1f827560be24f58798cb94b16f5d3387e6d3b68`.

`tools/bench-terrain-quickjs.sh` copies (without modifying) the vendored desktop host to task scratch space and includes `tools/terrain-quickjs-bench.rs`. The test boots the real `Runtime`, QuickJS `Guest`, native TILESET decoder, and `UiSurface`. It measures 600 stable frames and three full sweeps through all 263 maps at each viewport; command assignment and validation are outside the timed frame.
