# G1: full Tuxemon event importer

Status: complete for the v1/P1 scope.

## Delivered

- `bun run import` reads the pinned Tuxemon tree (default
  `/var/tmp/tuxemon-src`, overridable with `TUXEMON_SRC`) and generates one
  `rpgkit-project/v1` project containing all 263 maps.
- TMX events, same-name YAML, scenario YAML, and the seven runtime
  `load_yaml spyder_cathedral` sites are merged in Tuxemon load order.
  Dynamically loaded events use a per-map gate set by the original action.
- String game variables use a globally sorted enum table. The generated table
  has 493 entries: all 486 source variables plus seven importer-owned
  `load_yaml` gates; all 19 source variables with no statically known enum
  value remain visible with an empty value list.
- Guard shape selects `action`, `playerTouch`, `autorun`, or `parallel`.
  Compound blocking guards use a derived-switch evaluator; overlapping cell
  triggers are merged so all guards are sampled before any body runs.
- Dynamic NPC creation/removal, NPC talk chains, en_US PO lookup and dialogue
  pagination, choices (including nested pages above four choices), transfers,
  items/gold, variable operations, trackers, and keyed removable collision
  rectangles are lowered to the current 17-op runtime.
- Trainer, double, and scripted wild battles use the visible auto-win P1
  placeholder and update outcome, defeat, count, last-result, last-winner, and
  last-trainer state. Random encounters are deliberately silent. Player
  monster grants/removals maintain placeholder party state.
- Terrain remains the agreed G1 placeholder: one passable tile plus closed TMX
  collision rectangles. G5 owns real tiles, layers, flips, animation, and
  streamed rendering.

## Integrity and deterministic output

`bun run import` reports 0 schema errors and the recursive transfer audit
reports 0 missing or out-of-bounds destinations. Three bad coordinates in the
upstream source are repaired by a bounds clamp followed, when necessary, by a
fixed-order four-neighbour BFS for the nearest cell with a walkable exit:

- two materializations of `leather_town -> flower_city (59,0)` become
  `(38,3)` after the clamped `(39,0)` cell is found to be isolated;
- `water_volcano_path -> water_volcano_village (20,0)` becomes `(19,0)`
  for the 20x30 target (the clamped cell is already walkable).

Two consecutive complete imports produced the four identical hashes shown
above. The automated byte-stability test also builds twice in one process and
compares the complete project, enum table, and report serialization.

Tuxemon does not queue a source event that has neither a condition nor a
behavior. The importer now drops all six such events with an explicit coverage
reason instead of creating an unconditional autorun; this removes the
`spyder_cotton_cafe` “Rand facing” loop. A headless regression enters the cafe
at (8,10), holds a direction for 300 frames, and verifies that the player
moves. The sole zero-size TMX event (`tt_paper_town` “Teleport to Sea Route”)
is also dropped because its integer tile boundary can never contain a player.

## Coverage

Coverage uses the source-file census (shared scenario YAML counted once), but
each disposition is recorded by the actual converter branch used by the first
map-id-sorted materialization. If a whole event is omitted, all its source
actions and conditions are Dropped:

| Kind | Kinds | Uses | Native | Degraded | P1 placeholder | Dropped | S1 T1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Actions | 98 | 13,617 | 6,161 | 2,822 | 433 | 4,201 | 6,099 / 6,246 (44.79% / 45.9%) |
| Conditions | 64 operator/type pairs | 8,663 | 3,529 | 1,238 | 850 | 3,046 | 3,529 / 4,591 (40.74% / 53.0%) |

T1 coverage counts only uses whose effective disposition is Native or
Degraded. The old type-only table reported action Native as 5,448 / 13,617
(40.0%); it did not reflect per-instance branches or events discarded by a
fixed-false guard. Conversion-path accounting supersedes it. For example,
`char_face` is now split 869 Native / 440 Degraded / 718 Dropped,
`char_move` is 9 Degraded / 68 Dropped, all 1,008 `is char_facing` conditions
are Dropped in v1, and both 83-use monster health/status actions are Dropped.
Including v1 lowerings and deliberate P1 placeholders, effective executable
coverage is 69.1% for actions and 64.8% for conditions. Every source type,
count, and disposition reason is in `dist/import-report.json`; the human table
is in `findings/G1-coverage.md`.

## Remaining v1 degradations

These are intentionally recorded, not hidden:

- K1-dependent event areas, facing-aware page conditions, per-visit
  `local.*` reset, dynamic placement, and cross-event input locks are lowered
  where possible. Large random-encounter areas are silent in P1; whole-map
  visit trackers are lowered to guarded parallel events.
- K2-dependent arbitrary-event routes and runtime pathfinding remain dropped;
  player/self routes and NPC random wandering are retained.
- Music is silent and other presentation/meta actions remain dropped.
- Combat/monster internals remain P1 placeholders; P2 will replace them.
- Four of five keyed collision removals are backed by source collision
  rectangles. `spyder_dragonscave` requests key `drokoro`, but its TMX has
  no collision object with that key; the action is harmless and the upstream
  data defect is preserved in the coverage accounting.
