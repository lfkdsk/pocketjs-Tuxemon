# G7 — game-side lazy map repository

## Result

PASS. The shipped entry now embeds a 61,846-byte `ProjectShell` and acquires
the current map from the kit `MapRepository`; it no longer embeds the
12,766,698-byte, 263-map project document. On the release QuickJS desktop
host, startup through the first painted frame is 181.787 ms at 480×272 and
169.096 ms at 960×544, both below the 250 ms limit. First-frame live heap is
6.34/7.12 MiB. The maintained journey, attract replay, saves, four visual
goldens, locks, and freeze scans remain equivalent.

## Import and packaging

`gen-assets.ts` keeps `dist/project.json` only as an out-of-bundle parity
oracle. It passes that complete document to the kit's `splitProjectMaps`,
then emits:

- `dist/project-shell.json`: 61,846 bytes, including all 263 `mapIndex`
  records and the manifest/schema identities;
- `dist/maps/*.json`: 263 canonical ASCII entries totalling 7,374,469 bytes;
- 263 matching raw pak records under the exact `maps/<id>.json` keys;
- `GAME_ASSETS.maxActors = 500`, calculated over the complete source corpus,
  so lazy residency does not change the fixed render-node pool.

The splitter performs complete build-time schema validation. Repository tests
independently regenerate the split, compare every byte and SHA-256, assert
that the shell contains no `maps`, and acquire/release all 263 entries through
`createJsonMapRepository`. Two isolated complete cooks produced the same 2,652
files, 54,632,419 bytes, and aggregate SHA-256
`9bff0c7e1f76364f88490d493f2f2f7caa62dd5f951b3326af4e4e1a1fe84b9b`.

The pak grows because it now carries the independently addressable map data;
the important change is that the JS parser and heap see only the shell and the
resident map:

| release desktop artifact | inline baseline | lazy repository | change |
| --- | ---: | ---: | ---: |
| JS bundle | 19,331,463 B | 1,098,633 B | −94.3% |
| pak | 26,266,544 B | 33,656,192 B | +28.1% |
| project metadata parsed at boot | 12,766,698 B | 61,846 B | −99.5% |

## Runtime sources

`main.tsx` constructs the repository from the shell and passes it to
`GameView`. Desktop selects the synchronous `data.fs` byte reader; the
launcher stages all 263 entries under the app-scoped data root before boot.
Web and pak-capable hosts select `pakGet`. The web player installs the complete
pak before evaluating the bundle, so this local source is synchronously ready
and no network timing enters the reducer; an asynchronous `prepare` barrier is
not needed for this packaging mode.

Only the current map remains resident after a transfer. Corpus-wide static
checks deliberately reconstruct an inline view *from the production shell and
entries*, rather than bypassing the new artifacts.

## QuickJS performance

Measurements use the release Rust desktop host with the real rquickjs guest,
`UiSurface`, supervisor, and G6's 2,728-frame journey. Map files are installed
before the boot timer starts. No Bun/JSC time is reported.

| viewport / metric | inline baseline | lazy repository | acceptance |
| --- | ---: | ---: | ---: |
| 480×272 startup → first paint | 863.684 ms | **181.787 ms** | ≤250 ms |
| 480×272 first-frame QuickJS live heap | 36.05 MiB | **6.34 MiB** | −82.4% |
| 480×272 walking total p95 | 1.093 ms | **1.093 ms** | no regression |
| 480×272 map-switch total max | 3.723 ms | **14.282 ms** | ≤50 ms |

Both QuickJS runs finish at `spyder_route1` and produce the pinned canonical
terminal state SHA-256
`937ca7f719f79d2a1de6c6d22b7a4827ef9cae378904c254e7bcf592be56eb48`.

The same benchmark also starts every map with empty repository/session caches
and times the three kit preparation units separately: byte read + ASCII decode
+ JSON parse, structural validation, and world + passage compilation, followed

non-exempt visit is `buddha_mountain` at **49.840 ms**; the specified
`test_npcs` exception is 65.787 ms. The complete per-map table is
[`G7-map-first-visits.tsv`](G7-map-first-visits.tsv).

## Behavioral equivalence

- The inline and lazy sessions have canonical byte-identical `SessionState`
  at frame zero and after every one of the 2,728 journey frames. The lazy
  session also proves that exactly its current map is resident.
- Attract replay compares every host frame at 60, 30, 20, and 4 Hz. Every run
  finishes Route 1 at tile `(14,19)` with the same terminal state hash.
- The built PocketJS/WASM bundle completes two full journey runs with identical
  per-frame pixels; all four maintained PNGs and their semantic player, NPC,
  terrain, building, water, crop, and forest assertions remain unchanged.
- A save made on `spyder_downstairs` is restored after that map has been
  evicted while play has advanced to `spyder_paper_town`. The restored lazy
  state equals inline, only the restored map is resident, and a valid but
  different content manifest is rejected before reading the destination.
- The production-shard lock scan covers 319 pages / 323 lock commands:
  317 unlock and 2 transfer, with 0 unresolved, errors, or exceptions. The
  263-map freeze scan reports 0 permanent locks, blocking fibers, or errors.

## Host and visual acceptance

The release desktop build stages exactly 263 data files and builds its host.
The web build emits the same 1.10 MB game JS and 33.66 MB pak. Headless Chrome
runs the root and `/pocket-rpgkit/` forms, verifies whole-device-pixel sizing
at 2× and 1.25×, exercises the phone layout, and reports 30 successful requests
with no console errors. Manual inspection of the generated desktop-width and
phone screenshots confirms the bedroom, 16×32 player, dialogue panel, and
touch controls are visibly correct.
