## 结论与范围

当前结论为 **PASS**。J2 已从冻结的 J1 终态通过真实 input masks 续录到
`v.hospitalcure=1`，独立段、frame-zero 合并、save/load、KR2 rewind、60/30/20 Hz、六张
golden、CI 步骤以及全部父线回归均实跑通过。Greenwash 的阻挡来自原作设计的正门 Looten
guard；正确路线是 Candy greenhouse → Greenwash 上层 → level 2 → 下层 Looten，不是 importer
漏图层、漏碰撞或漏 transfer，因此没有修改 importer、RPG Kit 或 PocketJS。

J2 从 J1 的 `spyder_mansion@1,13`、`v.captainreturns=1` 终点继续，只记录 60 Hz
input masks，经 Mansion Top、Flower Dojo、Nimrod、Route 5、Timber、Scoop、Tunnel、Route 6、
Candy Town、Greenwash 和 Candy Hospital，停在 `spyder_candy_hospital3@5,7`。终点已经取得
cure，但刻意没有向南触发后续 Billie 事件；冻结终态应保持 `v.hospitalbillie=0`。

范围内没有直接写战斗胜负、剧情变量、物品或玩家坐标。`tools/j2-journey.ts` 通过生产
`Session`、真实移动/交互和 GB6 的确定性自动战斗接口生成按键输入；J2 文件只保存父段身份、
masks、检查点和哈希，不嵌入父 tape 或 terminal snapshot。

## 2. 剧情路线与原作逐事件对照

对照基准为只读上游 checkout `/var/tmp/tuxemon-src`，revision
`9e6258ff726b786040a267e8bdbbf037b560285e`。下列每一步均同时核对了上游事件定义、当前导入
`dist/project.json` 的对应命令，以及 J2 driver 的真实输入路径。

1. **Mansion 魔术师。** 上游 `spyder_mansion_top.tmx:204-208` 在与 Lenny 对话时
   `add_item dojo_pass` 并设置 `dojomagician:yes`。J2 从父终点上楼，对话后断言 pass 和变量均存在。
2. **Flower Dojo。** J2 先在 Flower Center 回血，依次完成 Dojo 2 的 Toph、Sokka、Kataro、
   Yangchen、Iroh、Wan，Dojo 3 的 Ares、Orion、Hermes、Hephastus、Saturn、Tu，再在 Dojo 4
   选择 `Strength` 完成 Thri。上游 `spyder_dojo4.tmx:86-103` 的两个选择分支都会设置
   `dojothrimonster:yes`；J2 随后按原作触发离场 Billie 战。
3. **Nimrod。** credential 使三层通路可走；J2 从东侧 bottom 经 middle/top 到西侧 bottom，
   击败 Tru。上游 `spyder_nimrod_bottom.tmx:138-159` 创建 Tru、配置
   Grimachin/Tigrock/Komodraw/Sharpfin/Embazook 并按 battle outcome 开门；冻结战斗与该队伍一致。
4. **Timber 首访。** 上游 `spyder_timber_town.tmx:159-172` 的 `seentimber` 是
   `is char_at player` 的触格事件，不是入图 parallel。实测入图 `(4,0)` settle 后仍为 0，踩到
   `(4,1)` 才变为 1；J2 显式走这一步，再去 Timber Center 回血。
5. **Scoop / Landrace。** 上游 `spyder_scoop4.tmx:136-157` 先启动 L40 Sludgehog 野战，
   再设置 `scooplandrace:yes`；`spyder_tunnel.tmx:266-302` 在变量未设置时把玩家从北端阻挡格
   送回 `(14,1)/(15,1)`。局部探针复现了阻挡，所以 J2 先完整穿过 Scoop 1–4 并赢下
   `wild:sludgehog`，没有伪造开门变量。
6. **Tunnel 跨层。** 上游真实可达序列为：Tunnel `(14,0)→(12,2)`，6 格且末步 UP，传到
   Below `(7,2)`；Below 走到 `(13,25)`，共 39 格，再向右踏入 `(14,25)`，在该格第一次执行
   commands 时必须 facing DOWN，传到 Tunnel `(5,27)`；最后 24 格、末步 RIGHT 到 `(19,35)`，
   传至 Route 6 `(0,15)`。合计 70 格。上游 `spyder_tunnel.tmx:44-65,84-90` 与
   `spyder_tunnel_below.tmx:90-112` 明确给出这些 transfer/facing 条件；中间
   `(13,14)→(6,16)→(5,26)` 是回环，不是进展路线。这里的难点是 Below 的 DOWN 检查位于
   commands 内：简单的 `goTo + pulse` 会在首次求值时保留 RIGHT；J2 因而从 `(13,25)` 向右进入
   并在移动 ticks 中保持 DOWN。
7. **Route 6 Gunner。** 上游 `spyder_route6.tmx:357-374` 在 `(30,17)` 创建 Gunner，talk
   事件位于 `(29,17)`，战后 NPC pathfind 到 `(28,17)`。J2 从 `(30,16)` 朝下交互，避免玩家占住
   NPC 的第一步；这是真实门卫事件，不是寻路器直接穿过。
8. **Candy 首访。** 上游 `spyder_candy_town.tmx:213-218` 是无 `is char_at` 条件的 parallel
   事件，因此入图 settle 即设置 `seencandy:yes`。它与 Timber 的触格语义不同，J2 没有增加
   人工踩格。
9. **Greenwash / Looten / Aardant。** J2 从东侧温室进入 Greenwash，再经 level 2 回到
   Looten 所在下层。上游 `spyder_greenwash.tmx:61-81` 固定 Looten 的 Bearloch、Rocktot、
   Foxko、Agnsher（均 L35）队伍，胜后执行 `add_item aardant`；冻结第 56 战、物品数和剧情值一致。
10. **Hospital 密码、scanner 与 cure。** 上游 `spyder_candy_center.yaml:24-63` 给出颜色选项和
    数字选项，仅 `blue` / `10` 传送 Hospital 2，并立即 clear 两个 passcode 变量。J2 通过分页
    选择输入 `2° Floor → Next > → Blue → Next > → 10`。上游

### 2.1 Greenwash 不是 importer 缺陷

最初把 Candy Town 主门 `(25,23)` 无法进入视为 transfer/importer 问题是不成立的：

- 上游 `spyder_candy_town.tmx:171-176` 的确在 `(25,23)` 定义到 Greenwash `(6,31)` 的 transfer；
- 同一上游文件 `:268-279` 又明确在 `(25,24)` 创建 guard，条件是 Looten 尚未胜利。guard 正好
  阻断从南侧靠近主门的路线，这是作者设计的前置门；
- 同一文件 `:260-266` 还无条件提供 `(30,21)` 到 `spyder_greenwash_greenhouse@25,15` 的入口；
- 当前 `dist/project.json:329840-329917` 保留了 `(30,21)` greenhouse transfer，也保留了
  `(25,24)` guard 及 `battle_outcome(...spyder_greenwash_looten, negate:true)` 条件；
- 冻结输入实际按温室 → Greenwash → level 2 → Greenwash 的原作路径到达 Looten，并在胜后从
  主门返回 Candy Town。

因此这里不需要 importer、RPG Kit 或 PocketJS 修复；正确修正是 Driver 走上游提供的替代入口。
