# G6 first playable milestone: events, terrain, characters, and shell

## Result

G6 is a playable P1 milestone generated from the pinned Tuxemon checkout at
`9e6258ff726b786040a267e8bdbbf037b560285e`. It boots directly into the Spyder
campaign at `spyder_bedroom`, renders the original streamed terrain, places
Tuxemon NPC/player art, runs K1 event semantics, and reaches `spyder_route1`
through dialogue, transfers, a wandering NPC interaction, the Paper Scoop
store scene, the first-monster choice, and the visible Billie battle
placeholder.

There are no per-map or per-character patches. `bun run import` and
`bun run gen-assets` are aliases for the same complete cook in `gen-assets.ts`:
it imports all events with the K1 profile, applies G5 terrain, cooks R2
characters and animated tiles, and rewrites the project, manifests, coverage,
and generated UI asset module.

The campaign chooser is intentionally skipped: the generated project starts in
Spyder's bedroom. The imported first prompt still lets the player skip the
opening presentation, which is the route used by the maintained journey.

## K1 activation and pre-switch fixes

The production import profile enables `areas`, `facing`, `condAll`,
`localReset`, `place`, and `inputLock`. `routes` remains `false` until K2 is
merged.

Before enabling that profile, the following review findings were fixed and
covered by regression tests:

- K1 areas are partitioned by exact event-membership signature. At overlaps,
  all source guards are sampled into local flags before any matching body runs.
  This preserves the same-cell merge semantics for Paper Town's overlapping
  `Stop!`, `Autosave Cotton`, and `Mom Quest Intercept` strip.
- Blocking spawn events keep their fiber alive after writing their own
  `local.npc.*` presence variable. The `tuxe_mart_taba` professor sequence now
  reaches both “I'll take 12 potions please.” and “My name is Kay Wren”, writes
  `v.proftalk2`, and returns control.
- If a source map contains a lock but no unlock action anywhere, importer-owned
  safety repair appends an unlock to the affected page. This is a corpus-level
  rule, not a map-name exception. The resulting full-corpus scan has no
  permanent locks.
- The default-profile compatibility test now compares the actual serialized
  bytes to the fixed SHA-256
  `36fa563fb94d66c720159ef064db23b32669e6dc9a94864a57d44ef1b0745820`;
  it is no longer a self-comparison.
- The smoke driver turns on an exit mat before advancing, so K1's retained
  facing predicate sees the intended direction.

`bun tools/frozen-k1.ts` entered every imported map at a known inbound landing
(or its centre), advanced dialogue, and drove all four directions for 12,000
frames per map. A lock or main fiber had to make no progress for the final
6,000-frame window to count as permanent. Result: 263 maps, 0 permanent input
locks, 0 permanent blocking fibers, and 0 interpreter errors.

G5's 14 labelled collision cells are excluded from immutable passage and are
materialised as invisible two-page event bodies. Their first page blocks;
`remove_collision` writes the map-local variable that activates a non-blocking
second page. All five source `remove_collision` actions resolve to these
variables.

Tuxemon's 48×128 walker sheets are decoded into R2's four-facing 16×32 idle,
left-step, and right-step frames. Indexed-colour images are normalised to RGBA,
and non-power-of-two static objects are transparently padded for portable
PocketJS compilation. The player uses `sprites/adventurer.png`. Terrain
animation references are mapped to R2 `animated` placements backed by 86
deduplicated RGBA atlases.

The complete generated tree was cooked twice in isolated roots. Both runs
contained 2,388 files and 46,435,818 bytes with aggregate SHA-256
`e654c20f181fd48c572cea43a49c43e7f123ca211d49616ea163ae86f6b34045`.
The normal worktree was clean after a further cook.

## Game shell, desktop, and web

`main.tsx` mounts RPG Kit's `GameView` with the generated streamed world,
16×32 characters, native animated tiles, and a Tuxemon-coloured dialogue
theme. `pocket.json` defines a fixed 480×272 integer-fit viewport.

- `bun run desktop` cooks the world, resolves the manifest, builds the
  `linux-app` bundle and release desktop host, then launches the host. In this
  headless worker there is no X/Wayland display, so acceptance used
  `bun run desktop --build-only`; the same release host's actual Runtime,
  rquickjs Guest, and UiSurface were then exercised by the journey benchmark.
- `bun run web` emits the landing page and game under `dist/web`.
  `bun run web:verify` launched headless Chrome and passed the landing card,
  preview, root and `/pocket-rpgkit/` subpath, fixed viewport at 2× and 1.25×,
  320 px phone controls, 30 network requests, and clean console checks.

## Deterministic journey

The adaptive reducer driver has 12 story assertions and is checked at 60, 30,
20, and 4 Hz. Every rate observes the same ordered dialogue/choice/transfer
beats and finishes at `spyder_route1 @14,19` with the same story state:
`intro_scoop`, `spokenmom`, `dantebin`, `firstfightend`, `firstfightdue`, and
`sys.party_size` are 1, and `bo.spyder_billie.won` is true. Two 60 Hz adaptive
runs also produce identical masks and result SHA-256.

The 12 assertions cover the Paper Scoop storekeeper and choice sequence,
bedroom/downstairs/Paper Town/Route 1 transfers, NPC spawn and talk, K1 facing
and overlapping-area behavior, first-monster acquisition, and the visible
`[BATTLE] Billie (P1 placeholder: the player wins)` result branch. K4 is not in
this baseline, so this milestone claims the imported shop scene, not inventory
purchase UI; general `open_shop` remains reported as dropped pending K4.

## Desktop QuickJS performance

`bun run bench:g6:quickjs` copies the vendored desktop host into
`/var/tmp/fleet/1833`, includes the G6 Rust benchmark, boots the real rquickjs
Guest plus `UiSurface`, and replays all 1,684 maintained frames. It records 600
walking samples, 119 transfer/fade samples, and five transfers per viewport.
These are CPU submission measurements; they do not substitute Bun/JSC for the
guest runtime.

| Viewport | Startup to first frame | Walking QJS p95 / max | Map-switch QJS p95 / max | Walking total p95 / max | Map-switch total p95 / max |
| --- | ---: | ---: | ---: | ---: | ---: |
| 480×272 | 913.577 ms | 18.011 / 22.763 ms | 22.160 / 227.541 ms | 18.093 / 22.797 ms | 22.621 / 230.813 ms |
| 960×544 | 914.049 ms | 18.200 / 22.897 ms | 19.357 / 230.736 ms | 18.402 / 22.931 ms | 19.963 / 234.099 ms |

This milestone is functionally playable, but it does not meet a 16.7 ms CPU
frame budget on this Intel Xeon w5-3435X host: walking p95 is about 18.0–18.2
ms, and the worst transfer is about 231–234 ms total. The dominant cost is the
full event/UI QuickJS workload rather than viewport scaling. This is recorded
as explicit follow-up performance debt, not hidden as a passing metric.
