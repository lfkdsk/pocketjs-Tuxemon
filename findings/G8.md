# G8: K4 upgrade, native Tuxemon shops, and battle-transition budgets

Date: 2026-09-29

## Result

The game now pins Pocket RPG Kit at
`fdc54ca017af5edb69b63c47bded77a5f6c02ff7` and imports Tuxemon item
economies as native K4 `shop` commands. All 21 `both_item` call sites are
native; the seven `buy_monster` call sites remain visible placeholders. The
imported catalog, per-shop buy and sell prices, finite stock, variable-gated
goods, sellability, and the 99-kind backpack limit are generated from the
pinned Tuxemon source rather than hand-authored per shop.

The maintained QuickJS journey now identifies the battle-entry frame and the
battle-exit frame separately and fails if either total frame cost exceeds
50 ms. Both target viewports pass. The full acceptance suite passes after one
stale exact-object assertion was updated to include the intentional inventory
configuration.

## Pocket RPG Kit upgrade

The upgrade commit `5d465bd` changes only the `vendor/pocket-rpgkit` gitlink,
from `4e5d880` to `fdc54ca`. K4 provides the `shop` command and its per-shop
`price`, `sellPrice`, `stock`, and `condition` fields, persistent
`SwitchState.shopStock`, `Item.price` / `Item.sellable`, `sellList`, inventory
limits, scrolling choices, longer labels, variable operands, and safe-integer
numeric banks.

The expanded modal union is handled by explicit `kind` narrowing in the
journey driver. A shop modal is cancelled; text and choices retain their prior
handling. No `as any` was introduced.

interpreter's mirrored switch state. The first post-upgrade 480×272 run wrote
SHA-256 `449c38b52331133ab10cea7293bff56a60f993a2d088d5bc6ccf072b8b09088c`.

The structural diff contained exactly these two additions:

Only after that proof were `tests/g7-repository.test.ts` and the QuickJS gate
repinned to `449c38b5…09088c`. Both viewports independently produced that new
complete-state hash.

## Automatic economy and item import

`importer/project.ts` reads every sorted YAML document under
`mods/tuxemon/db/economy` and `mods/tuxemon/db/item`. Item slugs are the
identity key; duplicate upstream `cream_puffs` definitions retain the first
deterministic definition. There are 230 source item rows and 224 unique item
slugs. The generated project has 225 items because the event corpus also
references the absent upstream slug `elianeoutput`, which uses the same
deterministic fallback path.

The source and generated-shop census is:

| Property | Result |
| --- | ---: |
| Economies | 14 |
| Item goods | 75 |
| Monster goods | 10 |
| Finite-stock item goods | 6 |
| Variable-conditioned item goods | 4 |
| Explicit sell prices unequal to `floor(price / 2)` | 18 |
| Largest shop | `spyder_timber_scoop`, 19 goods |

Every imported item receives its translated English name, intrinsic price,
`WorldState` usability, and `behaviors.resellable` as `Item.sellable`. Every
item-economy row becomes a `ShopGood` with its upstream `price`, `cost` as
`sellPrice`, non-negative finite `inventory` as `stock`, and economy variable
conditions lowered through the generated enum table. Shops use their economy
slug as the stable stock namespace and `sellList: "hide"` for Tuxemon's
resellable-only sell view. `set_economy` is represented as a build-time static
NPC-to-economy binding. The project sets
`system.inventory.maxKinds = 99`.

Coverage changed as follows:

| Action | Before | After |
| --- | ---: | ---: |
| `open_shop` Native | 0 | 21 |
| `open_shop` Placeholder | 28 | 7 |
| `set_economy` Native | 0 | 16 |

All seven remaining `open_shop` placeholders are `buy_monster`; each still
emits a visible `[SHOP]` message and stock summary. The complete action
coverage is now 11,574 Native, 638 Degraded, 27 Placeholder, and 1,378
Dropped out of 13,617 uses. Conditions remain 7,664 Native, 93 Degraded, one
Placeholder, and 905 Dropped out of 8,663 uses.

### Explicit degradations

- Tuxemon sends a 100th distinct item kind to a locker. Locker overflow is
  outside this task, so K4 refuses that purchase; the coverage report records
  the loss explicitly.
- K4's `rpgkit-project/v1` `Item` has no description field. All 224 translated
  descriptions are retained at
  `dist/import-report.json.economy.itemCatalog.descriptions`, including
  `potion = "Heals a monster by 50 HP."`, but they cannot yet be represented
  or displayed by the project item schema. This is recorded as Degraded, not
  silently discarded.

## Real-shop session tests

`tests/shop-import.test.ts` extracts the actual imported commands and item
catalog rather than recreating shop rows in a fixture. Its focused run is
2 pass / 0 fail / 82 assertions.

The Cotton Tech flow starts with 10,000 gold and executes through the normal
session reducer at 60, 30, 20, and 4 Hz:

1. buy `miaow_milk` for 2,000 (gold 10,000 → 8,000);
2. enter the sell tab and sell it at that shop's explicit 400 buy-back price
   (gold 8,000 → 8,400);
3. buy the one-stock `tm_avalanche` for 2,000, persist stock at
   `spyder_cotton_tech:tm_avalanche = 0`, and verify a second purchase is inert;
4. close the shop, create a checksummed session envelope, restore through the
   public save API, and verify gold, items, and exhausted stock;
5. compare all four host-rate summaries byte-for-byte.

The Flower Scoop test takes its `v.daytime` enum codes directly from the
imported goods and verifies that `tuxeball_diurnal` and
`tuxeball_nocturnal` are mutually visible in the correct states.
